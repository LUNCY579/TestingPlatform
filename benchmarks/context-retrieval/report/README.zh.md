# 本地检索工程报告

[English](README.md) | 中文

## 摘要

原生 Cordis 组合支持工作区和历史会话检索、显式作用域记忆，以及有预算限制的来源关联上下文。Zvec 保存持久记录；真实 turbovec 是可选的临时稠密重排器。本地确定性工作流和原生基准已在 macOS arm64 上运行。按用户选择，真实模型推理和神经嵌入质量验证仍待完成——本机没有提供方密钥，也没有可达的嵌入端点；本结果适用于本地实验，不构成多用户生产批准。

<a id="architecture-and-scope"></a>
## 架构与范围

[packages/retrieval](../../../packages/retrieval/README.zh.md) 下的四个包分别提供服务定义与编排（`retrieval`）、本地或 HTTP 嵌入（`retrieval-embed`）、原生存储与隔离 Python 工作进程（`retrieval-zvec`），以及九个代理工具和可选的步骤前上下文（`retrieval-tools`）。基础 bundle 的五个插件条目默认禁用；[覆盖配置](../../../apps/cli/config/examples/retrieval.yml)可启用它们，无需修改代理循环或模型适配器。[指南](../../../docs/user/guide/local-retrieval.zh.md)负责安装与恢复；[子系统参考](../../../docs/subsystems/retrieval.zh.md)负责 API 语义。

工作区同步处理哈希、编辑、重命名、删除、排除规则、有界分块和中断写入。已授权的历史 Session 索引只读取用户与助手文本，不修改日志。显式记忆支持用户、工作区、会话和代理作用域，以及时间戳、归属、过期、精确去重、分阶段替换和可验证删除。不提供自动个人信息提取；个人持久化、历史索引、远程嵌入和自动上下文分别需要主动启用。

官方 [Zvec](https://github.com/alibaba/zvec) Node SDK 固定为 0.8.0（Apache-2.0）；[turbovec](https://github.com/RyanCodrai/turbovec) 1.1.2（MIT）通过真实 Python 绑定与 NumPy 2.3.5 运行。两个上游均无分叉。本适配器提供稠密余弦、全文和混合检索，不暴露稀疏向量 API。独立压缩检索作为组件参与基准，不作为持久记忆数据库提供。

## 实测结果

测量日期为 2026-11-01：Apple M2、八个逻辑 CPU、8 GiB 内存、Darwin 27.0.0 arm64、Node 24.22.1、Python 3.12.6。每个用例使用独立进程、单个构建与查询线程、并发一、种子 421337、归一化的 256 维特征哈希、64 个查询，以及精确 Float32 余弦排序真值。文本模板包含源码、文档、会话和记忆标签；它们是受控的合成词项语料，不能代表神经嵌入。[方法说明](../README.zh.md)定义测量端点和命令。

初始矩阵固定使用旧的 `hnswEf: 64`，每个用例只构建一次。原始 p50 的端点不同：基线启动 `rg` 并返回一个精确匹配；Zvec 和混合模式调用原生搜索；turbovec 扫描完整授权语料；组合模式调用完整的前十条服务。上下文 p50 使用统一的前六条、1200 估算词元预算服务端点。不能把原始列解释为功能等价或同召回率下的加速。

[原始矩阵](../results/matrix.json)和 [CSV](../results/summary.csv)包含全部样本、p95/p99、顺序吞吐量、recall@1/5/10、MRR、冷重开、嵌入时间、百分之一更新、CPU、磁盘和 IPC。基线 Recall@10 为 0.1，是因为它有意只返回一个正确来源，并非遗漏该来源。混合检索偏向词项证据，因此稠密真值召回率低估了其目标来源表现：在 100k 下，来源 hit@1 为 0.969，Zvec 则为 0.766。基线增量样本只测量真值嵌入，没有重写词项文件，因此 CSV 中该模式的增量更新字段留空。

每种模式保留同一真值矩阵；采样 RSS 包含该夹具、Node、原生与 Python 运行时，并可能重复计算共享页。它既不是纯索引内存，也不是比例驻留集。冷重开保留操作系统页缓存；临时 turbovec 还需要重新载入。压缩不会缩小作为权威存储的 Zvec 文件。构建时间差异很大（100k 组合模式耗时 1018 秒）；在运行中的 8 GiB 桌面上进行一次测量，不能可靠比较构建速度。同一图的查询样本并非独立总体重复实验，64 个样本不能确定稳定的尾部 p99。

测量日期为 2026-11-02，神经相关性框架 [neural/run.mjs](../neural/run.mjs) 在每个路径独立进程中，对 35 条合成片段与 45 个查询按 top-10、`minScore: 0.2`、`hnswEf: 2048`、种子 421337 打分。可运行的两条词项路径在改写、困难负例和标识符类别上 Recall@10 均为 1.000；关键词 MRR 为 0.721，特征哈希稠密 MRR 为 0.515。所有返回引用的来源链接有效率为 1.000。关键词查询 p50 为 1.14 毫秒，哈希稠密路径为 1.54 毫秒；在 256 维 `local-hashed` 空间 `sp:1a432a5391e0f78270fa3912` 中，两条路径的进程树峰值 RSS 分别为 172 MiB 与 166 MiB。两条路径都未达到预先声明的多语言与缺失证据目标：关键词 Recall@10 为 0.300，目标 0.350；哈希稠密为 0.000，目标 0.200；两者对五个无证据查询都没有弃权，关键词平均最高分为 0.799，上限 0.600。记录将这些保留为失败目标。神经稠密与混合路径待完成，因为不可达任何回环嵌入端点；`--selftest=true` 使用 token 摘要替代服务执行同一路径，并把结果标记为 `harness-plumbing`。[待完成记录](../neural/results/neural-pending.json)与[自检记录](../neural/results/neural-harness-selftest.json)保存完整输出。

<a id="quality-and-defaults"></a>
## 质量与默认值

另一项[同图扫描](../results/ann-sweep.json)以不同搜索深度重开同一个 100k Zvec 索引。采用的默认值为 `hnswEf: 2048`：在此语料上达到 0.958 Recall@10、1.0 Recall@1，原生 p50 为 3.49 毫秒。这是观测到的合成质量目标，不是普遍保证。尝试使用 4096 的运行[因原生上限而失败](../results/ann-limit-failure.json)；配置现拒绝超过 2048 的值。

| hnswEf | 原生 p50 毫秒 | Recall@1 | Recall@10 |
|---:|---:|---:|---:|
| 128 | 0.76 | 0.875 | 0.737 |
| 256 | 1.14 | 0.969 | 0.839 |
| 512 | 1.74 | 0.984 | 0.914 |
| 1024 | 2.55 | 1.000 | 0.944 |
| 2048 | 3.49 | 1.000 | 0.958 |

在同一图上的完整服务配对比较中，ef64 下组合模式 p50 为 2.02 毫秒、Zvec 为 1.72 毫秒；ef1024 下分别为 4.14 和 3.76 毫秒。所有组合查询实际使用了工作进程。这分别增加约 18% 和 10% 延迟，目标来源命中率没有变化，因此没有证据支持自动性能路由阈值，默认保持 Zvec。四位独立压缩比两位保留更多稠密召回（100k Recall@10 分别为 0.792 和 0.564），但本次扫描更慢，而且质量不同于调优后的 ANN。两位仍属实验功能；不声称同召回率下压缩更快。

<a id="packing-optimization"></a>
## 上下文打包优化

生产上下文打包对每次操作仅准备一次片段词元集合，不再对每一对片段重复分词。每个变体使用三个独立进程，每进程 100 个样本，使用可复现的[负对照补丁](../packing-negative-control.patch)。进程 p50 的中位数在 40 个候选时从 6.425 降至 0.610 毫秒（10.53×），在 100 个候选时从 40.378 降至 3.314 毫秒（12.18×）。所有前后输出哈希一致。[优化前](../results/packing-before.json)和[优化后](../results/packing-after.json)保留全部样本；没有证据显示显著内存节省。没有新增持久查询缓存。

## 安全与可靠性审查

独立组件审计和确定性对抗测试发现并修复了以下按优先级排列的缺陷。优先级描述部署后的可能后果，不代表已发布漏洞声明。回归证据位于所属包测试中。

| 优先级 | 已确认风险 | 修复与验证 |
|---|---|---|
| 高 | 作用域与路径混淆可能接纳其他工作区或错误执行环境。 | 主机派生的品牌类型身份、规范化原始 cwd、本地文件系统映射和原生先过滤谓词；跨用户、工作区、会话、代理及符号链接测试。 |
| 高 | 记忆替换中断可能隐藏前任记录而没有当前后继。 | 隐藏待提交后继、持久意图恢复、串行发布、显式未知结果；注入写入失败与重启检查。 |
| 高 | 静默删除或写入拒绝，以及不完整派生同步可能在陈旧记录仍存在时报告成功。 | 验证权威记录缺失与写入接受情况，作用域删除包含过期及被替换记忆，记录待写入来源 ID，从权威记录重建或回退；重启与故障测试。 |
| 高 | 环境 API 凭据、反射 HTTP 错误或重定向可能泄露私人输入。 | 默认凭据名为空、明确远程许可、回环与重定向检查、清理错误详情、有界 HTTP 正文和生命周期中止；本地 HTTP 对抗测试。 |
| 高 | 工作进程生命周期及竞争写入可能遗留资源或破坏共享所有权。 | 操作系统 SQLite 独占写租约、无凭据的有界隔离工作进程、等待活动及失败进程退出、串行排空关闭；锁、真实崩溃重启、超时及畸形协议测试。 |
| 中 | 构建后索引入口复制服务或错误类，大小写折叠隐藏不同事实，原生前缀限制隐藏授权记录。 | 公共入口转发及身份断言、区分大小写的精确去重、原生前缀谓词和显式枚举上限；构建消费者与对抗回归测试。 |
| 中 | 重复上下文去重与极小预算可能遗漏归属或抑制已更改事实。 | 已记录证据指纹包含内容与版本，完整空结果文本适配接受的预算，拒绝无效限制；工具测试与录制 Session 快照。 |

提示格式将检索文本标为不可信用户证据，并保留来源链接；它无法保证模型抵抗每一份恶意文档。秘密文件与忽略路径在读取前被排除，但文件名策略无法识别允许文件中嵌入的所有秘密。本地文件、存储、工作进程可执行文件及 Harness 主目录属于同一可信操作者。

<a id="workflow-verification"></a>
## 工作流验证

基于 Loader 的集成启动真实 Cordis 服务、真实 Zvec，以及能够调用工具的脚本适配器。它使用合成记录和真实工具分发执行 A–F；这验证编排与断言，不验证模型推理。[工作流指标](../results/agent-workflow.json)记录所有断言和估算输入计数。

| 场景 | 已验证观察 |
|---|---|
| A | 索引示例工作区；检索带路径与行号的函数证据；忽略的秘密夹具保持缺失。 |
| B | 在 Session A 显式记忆并关闭，在 Session B 检索，无需把 A 重放给 B。 |
| C | 更正合成值；检索接纳最新版并隐藏被替换前任。 |
| D | 遗忘并检查权威记录缺失，重启后确认检索仍为空；源日志保持完整。 |
| E | 可选后端不可用或不一致时，仍返回授权的 Zvec 权威结果。 |
| F | 同一存储中的其他工作区无法检索高度相似的受限事实；组件测试还覆盖用户、会话与代理隔离。 |

记录的热启动词项追问在 3.74 毫秒内到达首个包含证据的脚本模型请求。该次测量的模型输入估算从 2206 增至 2337 词元（+131）；这是新增证据，不是已验证词元节省。计数使用已说明的启发式，而非提供方用量。完整任务模型准确率、回答延迟、神经语义质量和词元节省仍未测量。后续 schema 或文案变更可能改变重新生成的夹具计数。

<a id="checks-and-working-tree"></a>
## 检查与工作区

初始实现检查包括 225 项定向测试、两项构建消费者 e2e 测试及一项真实模型跳过、14 项平台测试、94 组插件测试，以及两项选定的无密钥重放与语料检查。真实模型检索套件现已覆盖依赖证据的回答、跨会话回忆、记忆修正、重启后遗忘与作用域隔离；所有用例在没有 `DEEPSEEK_API_KEY` 时自动跳过，本机未执行其中任何一项。实现阶段的应用构建产物、Host 与 Client 聚合类型检查、全仓库 lint、启用与禁用两种 Web 冒烟测试，以及文档网站构建均通过。记录区分初始聚合失败与后续定向修复。

[验证记录](../results/verification.json)列出实际命令、退出结果、排除项及已修正的初次失败。它区分定向原生测试、构建消费者 e2e、无密钥重放、平台集成、启用和禁用两种 Web 冒烟测试，以及现有 Our Free Model 贡献者测试。真实提供方验证明确待完成。原始记录保留实现阶段观察到的全仓库失败。修复覆盖四份 README 配对、兼容外部打包的 workspace peer 声明、重命名检查缓冲区，以及固定导入源码的所有权范围。[仓库检查](../results/repository-checks.json)记录修复后的验证。

实现分支为 `feat/local-retrieval-readiness`。[文件清单](../results/working-tree.txt)记录发布前的已跟踪修改及新文件，包括四个检索包、夹具、配置、目录、基准源码与证据，以及平台冒烟覆盖。初始未完成检索修改已整合。初始无关的 `.installer-node-version` 和 `start-demo.command` 已保留。清单描述其捕获时间；后续提交与发布以 Git 历史为准。运行时索引、嵌入、Python 与 Node 安装及私有日志仍在 `.testingplatform/` 中被忽略。

<a id="readiness-and-limitations"></a>
## 就绪程度与限制

- 建议本地配置：Zvec、启用内存映射、单个查询与构建线程、hnswEf2048，确定性代码与词项实验使用本地特征哈希，或明确选择回环神经嵌入服务。turbovec、个人持久化、历史索引及自动检索在需要前保持禁用。
- 已验证平台仅为 macOS arm64。Linux 与 WSL 基准监督已实现但未在此运行；没有 Windows 原生监督器。原生 SDK、wheel 可用性及其他操作系统需要 CI 或对应主机验证。
- 可信本地主机不是经身份验证的多租户服务。每个操作系统操作者应使用独立存储与主目录。不声称远程租户隔离。
- 文件同步需要显式触发，不是连续监听或整个工作区快照事务。长时间同步原生调用无法在执行中中断；有界批处理允许在调用之间取消。
- 遗忘验证权威检索记录中的逻辑缺失，并丢弃压缩副本；它不是取证级擦除。历史 Session 消息、备份或独立索引的来源事实可能保留同样文本。
- 特征哈希是确定性词项投影，不是内置神经语义模型。嵌入空间变化需要独立索引；来源分块可以重建，但显式记忆需要有意识的迁移或备份。
- 真实可调用工具模型验证和神经检索相关性仍待完成：本机没有提供方密钥，也没有可达的回环嵌入端点。神经框架测量词项路径，并把稠密与混合记录为待完成而非通过；真实模型 E2E 套件在没有 `DEEPSEEK_API_KEY` 时自动跳过。没有私人文档被发送给远程嵌入提供方。
