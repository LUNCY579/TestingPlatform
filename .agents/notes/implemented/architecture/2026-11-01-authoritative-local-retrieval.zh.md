# Agent Note: 本地检索主存储与可重建压缩索引

Status: implemented

[English](2026-11-01-authoritative-local-retrieval.md) | 中文

## 问题

工作区证据、历史会话和显式记忆的权威来源不同。压缩相似度索引既不具备所有权元数据，也没有管理这些数据所需的事务保证。增加持久副本会使普通笔记本上的中断写入、删除和嵌入模型变更更难协调。

## 决策

[原生检索组合](../../../../packages/retrieval/README.zh.md)将 Zvec 记录和向量作为主存储。文件和原始会话日志拥有源文本，其片段属于派生数据。显式记忆是 Zvec 主记录，不能通过重建源索引来恢复。

turbovec 在单个隔离 Python 工作进程中运行，标准输入输出消息、队列、向量数量、截止时间和线程数均受限制。四位压缩副本是临时数据。主存储元数据在压缩评分前选择授权候选；缺失 ID、协议错误或工作进程退出都会回退到 Zvec。重建在不变的嵌入空间中重新嵌入授权主记录文本。

记忆替代会先写入隐藏的待处理记录，再更改前驱元数据并激活后继。作用域查询在读取当前记录前修复中断的持久意图。提交失败会报告 `outcome_pending`；取消并不意味着之前的持久写入已经消失。源同步使用独立的待处理 ID 日志，仅在写入被接受后发布已完成源记录。

主体和原始规范化工作区身份来自可信宿主配置及智能体状态。个人记忆和历史会话索引需要分别启用。该组合假定一个运维者拥有自己的 Harness 主目录，不提供共享服务的租户认证。

## 考虑过的替代方案

**将持久 turbovec 作为主存储：**它不提供服务所需的元数据过滤和记忆生命周期能力。临时派生索引避免了第二套崩溃恢复和删除主存储。

**强制启用压缩重排器：**[实测对比](../../../../benchmarks/context-retrieval/report/README.zh.md)保存性能证据。增加候选生成、序列化和进程分派并不等于提速；Zvec 保持为更简单的默认方案，两位压缩仍属于实验选项。

**假定多行操作具有原子性：**Node API 可能在后续标量更新失败前接受向量写入。分阶段发布和显式恢复替代了这一不受支持的假定。

**自动从会话提取个人记忆：**源索引和显式记忆保留的用途不同。个人保留保持默认关闭，并要求显式写入操作。

## 后果

主存储不受可选工作进程故障影响；模型通过已有工具和请求钩子接收已记录、带来源链接的证据。压缩不会减少主 Zvec 存储。同步原生查询和构建无法在调用中途被打断；更换嵌入空间需要独立索引及手工显式记忆迁移。

验证覆盖原生持久化、分域查询和修改、中断发布、工作进程崩溃和进程退出屏障、HTTP 取消、重建、免密 Loader 工作流及已录制会话回放。基准在独立子进程中运行构建后的 JavaScript 并保存原始测量；真实模型推理、神经嵌入质量及其他操作系统仍需单独验证。
