# Demo participant pack — read this first

You are the control group for a cost demo. You run each task once,
with predictive tooling OFF, in the harness you already have in this
checkout. You send Cheng a bundle per task. You do not run the meter,
you do not install a predictor, and you do not run anything twice.

## What is in this pack

- `TASKS.md` — the 8 fixed tasks. Prompt text is fixed: paste it
  verbatim. This copy includes the pristine-target note that clarifies
  how "suite green" is judged (see TASKS.md, "Pristine demo-target
  note"). Do not edit this file.
- `PARTICIPANT_CHECKLIST.md` — the step-by-step order: before, during,
  and after each run, plus the scrub step before sending.
- `RUN_SHEET_TEMPLATE.md` — copy it once per task, fill it in, and
  include it in that task's bundle. The reporter cannot judge success;
  you do.
- `preflight.mjs` — a stdlib-only Node check you run on your bundle
  folder before zipping. It catches missing files, blank run-sheet
  fields, leftover `<...>` placeholders, forbidden files (`.env`,
  keys), and a non-ZIP or empty session export. It does NOT read the
  inside of the export ZIP for secrets (compressed content cannot be
  searched this way) — the manual ZIP-content check in the checklist
  is still required.

## The workspace (do not get this wrong)

- The agent workspace is `demo-target/` inside this checkout, and
  ONLY that folder. Never point the harness at a personal project, a
  work repo, or any folder containing credentials.
- The harness itself is started from the TestingPlatform repo root
  (`pnpm run dev` there), not from inside `demo-target/` — running it
  inside `demo-target/` fails with "Missing script: dev".
- Before EVERY run, reset it from inside `demo-target/`:

```sh
git checkout -- . && git clean -fd
```

Or re-copy the pristine folder. A run's edits — and the
`.demo-registry.json` state file a run leaves behind — must never
leak into the next run.

- Pristine check (once, before your first task, then reset again):
  `npm test` in `demo-target/` must give **10 pass / 2 fail** — the
  two intended failures (`sumRange` and the registry suite-only test).
  If it gives anything else, stop and tell Cheng; do not run tasks on
  a dirty target.

## One task, in order

1. Reset `demo-target/`.
2. Open a harness workspace on `demo-target/` only.
3. Paste the task prompt verbatim from `TASKS.md`. No coaching, no
   correcting, no re-prompting mid-run. If it stalls, stop and mark
   the run failed — do not rescue it and report it as a pass.
4. Export the session (`/export` in the Web UI) and download the ZIP.
5. Copy `RUN_SHEET_TEMPLATE.md`, fill it in completely, and save it
   as `run-sheet.md` in the bundle folder.
6. In `demo-target/`, save the post-run state:
   `git diff > demo-target-diff.txt` and append `git status --short`.
   (For T1, `git diff` alone is empty because FINDINGS.md is a new
   file — the status lines are what show it. That is expected.)
7. Run preflight on the bundle folder (see below).
8. Do the manual scrub in `PARTICIPANT_CHECKLIST.md`, then zip the
   three files as `<participant-code>-<TASK>-control.zip` and send it.

Bundle folder (before zipping), exactly these three files:

```
<TASK>-control/
  session-export.zip
  run-sheet.md
  demo-target-diff.txt
```

## Preflight

From this checkout (Node 24+; no install, no dependencies):

```sh
node demo-pack/preflight.mjs --bundle <TASK>-control [--task <TASK>]
```

Exit 0 means the bundle structure passes (warnings are still printed
and must be read). Exit 1 means fix the listed errors and re-run.
Preflight passing does NOT mean the export contents are clean — it
cannot see inside a ZIP. Do the manual check anyway.

## What Cheng does on receipt

He runs the bill-audit reporter over your export (requests, tool-call
trajectory, official-list-price cost), checks your run sheet for
completeness, and only then counts the run as evidence. An incomplete
bundle goes back to you; he does not guess a missing field. A cheaper
failed run is not a win — success is judged from your run sheet,
next to cost.
